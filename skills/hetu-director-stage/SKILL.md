# 导演布景台

将剧本中的空间与动作变成可看的白模场景。作者可以只提出目标，由外部Agent操作插件；手工布景可选。白模用于空间、构图与节奏，不代表演员形象、最终质感或成片认可。

1. 通过河图`plugins.inspect`与精确作品连接发现活动包，再读取`plugins.capabilities`。固定包摘要、能力摘要与当前作品；不安装同名Codex插件，不新增MCP连接。
2. 读取已有场景的固定修订、来源和意见。新场景使用`save_scene`，空基线为revision=0、sha256=""；已有数据携带原CAS基线及原操作键。
3. 按需要建立程序白模、人物站位、机位、轨道及镜头区间。采用米、Y向上、度制旋转和整数帧；普通作者不用自己填写这些字段。字段及变换见[流程与数据](references/workflow.md)，动作由[操作地图](references/operations.md)定位。
   - 先区分基础布置与“只改这一镜”。局部调度使用`set_blocking`，绑定shot_id与对象ID，设置起始transform和可选end_transform；不要改全局人物去冒充局部走位。旋转沿最短角度插值，单帧只用起始值，邻镜恢复全局采样。
   - `put_shot`维护机位、区间、label与dialogue；台词为调度参考，引用正式剧本时追加固定source_ref再填source_index，不改正文。整表更新必须保留其他镜头的台词与blocking。
   - 有明确对话关系时用`set_direction`设置两个人物轴线和估算speech_rate（默认每秒4字词）。以`shot_report`固定修订、shot_id、frame与aspect读取站位、朝向、可能遮挡、跨轴和台词估时。镜头首帧检查不代替全程观看，几何与语速估算不冒充实际画面识别或声音时长。
4. 使用`render_plan`固定修订、机位、帧范围及分辨率。读取同包`scripts/render-stage.mjs`，对固定包执行无窗口Chromium渲染，无需河图GUI。PNG／GLB／序列是基础成果，MP4按需用FFmpeg编码；缺少浏览器或WebGL时明确失败，不拿空白图片冒充成功。
5. 核验真实输出、摘要与必要观看范围；需要进入河图素材库时发现当前公开素材导入能力，固定字节与真实来源及权利，按已有授权执行。图片文件、完整解码与作者认可分别判断。
6. 将意见固定到旧场景revision、目标及frame，保留origin。依据意见建立新修订或备选并回读旧、新结果。Agent自查不冒充作者意见；未知先`get_operation`，未确认前不换键重发。
7. 导出完整场景及渲染清单，保留来源和计划摘要。正式剧本、素材选用、付费调用和成片确认通过各自宿主能力与真实决定完成，不因白模保存而自动执行。

脚本和依赖的获取见[无窗口渲染](references/rendering.md)。同包资源经`skills.read`按需读取；脚本不包含模型调用。
