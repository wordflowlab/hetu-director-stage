# 开发发布与上架

## 开发与运行包

`npm ci`固定依赖，`npm run build`输出`dist`，仅包含运行后端、界面、共享渲染器、Skill及实际依赖许可。宿主SDK与Radix快照摘要由`vendor/sources.json`核验；不导入宿主内部源码。包使用Host API 1，完整GUI导出要求宿主0.11.2或以上的二进制导出服务；机器布景和同包无窗口渲染独立于桌面窗口。

## 无窗口渲染

从实际能力读取`render_plan`，将完整返回data写入本机JSON。使用同一固定包的脚本：

```bash
node dist/skills/hetu-director-stage/scripts/render-stage.mjs render-plan.json --package dist --output renders --browser /path/to/chromium
```

`--format`选择`png`、`glb`或`mp4`，MP4需`--ffmpeg /path/to/ffmpeg`。输出目录需要为空，不覆盖已有成果。脚本通过Node内置CDP操作本机Chromium，共享与GUI相同的Three.js场景模块；不需要河图GUI，不向远端服务发送作品。实际文件、manifest、计划摘要与固定来源一起交付。

## 发布及上架

正式安装验收复用同一套Electron旅程。使用`HETU_PACKAGED_APP`指向已安装的可执行文件、`HETU_TEST_BIN`指向该安装的`Contents/Resources/bin`、`HETU_TEST_PACKAGE`指向重新下载并解压的发行插件，再运行`npm run test:ui`。夹具清除开发入口覆盖，真实使用随包Rust、Node及插件管理器，并验证应用打包状态与版本；测试资料使用独立目录。

1. 完成单元、真实MCP、渲染、Electron与本对话旅程。
2. `npm run package`，检查归档内无AppleDouble、node_modules、凭据和私密操作引用。
3. 解压后用宿主`inspect_package`核对package_sha256，记录归档archive_sha256。
4. 在本次授权内提交源码、创建不可变`v0.1.0`标签和GitHub开发预览Release。
5. 重新下载Release，核对源码、两摘要与实际验收包。
6. 宿主插件中心登记固定版本、平台、下载和验收链接，构建测试后上线并核对公网中英路径与图片字节。

发行目录不自动安装，安装、外部Agent连接、作品管理与作者创作决定各自独立。插件升级不重写既有场景，未知操作保留旧义。Windows／Linux未经实机验收则明确标注。
